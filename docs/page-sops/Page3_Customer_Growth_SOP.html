0.2 — Verify [New Customers] before building anything that uses it
New Customers is used twice on this page (a KPI card and one bar series) and has never been checked in this build. Its counterpart [Churned Customers] — same shape, same table, same EventType pattern — had exactly this bug: a bare CALCULATE(DISTINCTCOUNT(...), EventType = "...") with no date restriction, which silently sums the entire 36-month window instead of one month.

Check now: open [New Customers] in the formula bar. If it has no YEAR(...) = ... && MONTH(...) = ... restriction on DimDate, apply the identical fix already used on Churned Customers: 
New Customers = 
VAR CurrentPeriodEnd = MAX ( DimDate[Date] )
VAR CurrentYear = YEAR ( CurrentPeriodEnd )
VAR CurrentMonth = MONTH ( CurrentPeriodEnd )
RETURN
CALCULATE (
    DISTINCTCOUNT ( FactSubscriptionEvent[CustomerID] ),
    FactSubscriptionEvent[EventType] = "New",
    FILTER ( ALL ( DimDate ), YEAR ( DimDate[Date] ) = CurrentYear && MONTH ( DimDate[Date] ) = CurrentMonth )
)
Validate: with no filters, it must return 177 (Dec 2025, per the validated Phase 3 figure). Do not build the KPI card or the bar series until this returns 177.

0.3 — Missing measures to create new

All are mechanical derivations of already-validated measures, following the exact Value/Caption/Color pattern already established on Page 1 — no new business logic.

_New Customers Delta Value = 
VAR Current = [New Customers]
VAR Prior = CALCULATE ( [New Customers], DATEADD ( DimDate[Date], -1, MONTH ) )
VAR pct = DIVIDE ( Current - Prior, Prior )
RETURN IF ( pct >= 0, "▲ +", "▼ " ) & FORMAT ( ABS ( pct ), "0.0%" )
_New Customers Delta Caption = 
VAR Prior = CALCULATE ( [New Customers], DATEADD ( DimDate[Date], -1, MONTH ) )
RETURN "vs " & FORMAT ( Prior, "#,##0" )
_New Customers Delta Color = 
VAR Current = [New Customers]
VAR Prior = CALCULATE ( [New Customers], DATEADD ( DimDate[Date], -1, MONTH ) )
RETURN IF ( Current >= Prior, "#16A34A", IF ( Current < Prior, "#DC2626", "#94A3B8" ) )
_Churned Customers Delta Value = 
VAR Current = [Churned Customers]
VAR Prior = CALCULATE ( [Churned Customers], DATEADD ( DimDate[Date], -1, MONTH ) )
VAR pct = DIVIDE ( Current - Prior, Prior )
RETURN IF ( pct >= 0, "▲ +", "▼ " ) & FORMAT ( ABS ( pct ), "0.0%" )
_Churned Customers Delta Caption = 
VAR Prior = CALCULATE ( [Churned Customers], DATEADD ( DimDate[Date], -1, MONTH ) )
RETURN "vs " & FORMAT ( Prior, "#,##0" )
_Churned Customers Delta Color = 
VAR Current = [Churned Customers]
VAR Prior = CALCULATE ( [Churned Customers], DATEADD ( DimDate[Date], -1, MONTH ) )
RETURN IF ( Current <= Prior, "#16A34A", IF ( Current > Prior, "#DC2626", "#94A3B8" ) )

Note the inversion on the last measure: fewer churned customers (Current ≤ Prior) is green — this is the "increase = negative" polarity the spec requires, same pattern as Logo Churn's card.

_Customer Base Composition Latest = 
FORMAT ( [Total Customers], "#,##0" ) & " total · " & FORMAT ( [Active Customers], "#,##0" ) & " active"
_New to Churned Customers Ratio = 
DIVIDE ( [New Customers], [Churned Customers] )
_Logo Churn Rate 12M Average = 
VAR CurrentMonthEnd = EOMONTH ( MAX ( DimDate[Date] ), 0 )
RETURN
AVERAGEX (
    GENERATESERIES ( 0, 11, 1 ),
    VAR MonthEnd = EOMONTH ( CurrentMonthEnd, -[Value] )
    RETURN CALCULATE ( [Logo Churn Rate], DimDate[Date] = MonthEnd )
)

Reused, not new: Net customer change and the net-adds strip both use the already-existing _Active Customers Net Change from Page 1 — mathematically, New minus Churned in a given month equals that month's change in the active count, so no separate "New minus Churned" measure is needed.

Implementation issue identified — 0.4: the approved "4× typical" secondary-axis formula
Existing approved decision: bound the growth-rate axis at roughly 4× the typical monthly growth rate, and set it on the secondary axis.

Issue: this exact formula, applied without checking the real data first, produced three consecutive broken results on the Revenue & Growth combo chart — the axis side was also swapped (columns are always primary, lines always secondary; there is no way to configure a Line and clustered column chart otherwise). Guessing a multiple of "typical" ignores that early-period rates are frequently the extreme case, not the steady-state case.

Impact: applying "4× typical" blindly here risks the identical failure — either the wrong axis gets bounded, or the bound clips too much or too little of the real Customer Growth % range.

Recommended action: do not compute a bound in advance. Step 5.5 below has you read the actual 36-month min/max of [Customer Growth %] directly from a temporary table visual before touching the axis property, and bound the primary axis (which carries the columns) based on that real range. This is implementation guidance, not a change to the approved design — the design still says "bound it near typical × a multiple"; this section only fixes how that number gets chosen.
Implementation issue identified — 0.5: the "visual-level negative representation" of Churned Customers
Existing approved decision: "no change to locked DAX... use a visual-level negative representation."

Issue: Power BI's Clustered Column chart has no field-well or format-pane toggle that flips one series to render below zero without the underlying value itself being negative. There is no "invert this series" setting.

Impact: without some negative value existing somewhere, Churned Customers cannot render below the axis at all.

Recommended action: add one new measure that is a pure sign-flip with zero interpretive content — it does not change what Churned Customers means, only how one chart plots it: 
_Churned Customers (Negative) = -[Churned Customers]
This is the same category of necessary, minimal exception already used for the "Total" rename workaround and the Contraction/Churned MRR sign convention on earlier pages — flagged per protocol, not silently added.
0.6 — final outcome: the simple version worked at rest but failed under filtering; the two-layer version in Section 4 is what shipped
This went through three stages worth recording, since each taught something real. First, the predicted limitation (a plain Area chart shades from zero) was build-tested and found not to apply — Shade area's per-series toggle produced a correct between-the-lines band on a single visual. Second, that single-visual version was then found to distort the axis (summing both series to ~8K when using Stacked Area, the type actually needed to get a between-lines fill in the first place). Third, once corrected to a genuinely separate shading layer plus a line layer, the two layers were found to drift out of sync whenever the Period filter was narrowed — the axes independently auto-scaled to slightly different values, separating the shading from the lines. The two-layer construction in Section 4, with both layers' axes hardcoded to an identical typed maximum, is what actually resolved all three issues, and it's been tested and confirmed stable at two different filter widths. Do not attempt the single-visual version — it is a known dead end for this specific effect.

Section 6 — Acquisition vs Churn Rate (supersedes the original Insight card)

Superseded — the narrative Insight card was removed after audit
The original design here was a text-based Insight card: an eyebrow, a narrative sentence built from _Customer Insight Text, three supporting rows, a footnote, and a navy rule — following Page 1's Executive Insight pattern directly. A dedicated review of the narrative-card pattern across Pages 1–4 found this specific card failed its own test: the sentence restated all five KPI cards sitting directly above it, in the same order, with zero synthesis. 6.1 — New measure required

New Customer Rate = DIVIDE ( [New Customers], [_Active Customers at Period Start] )

This shares its denominator with [Logo Churn Rate] exactly — both use _Active Customers at Period Start — which is what makes the two lines meaningfully comparable on one axis.

Reconciliation verified — the gap genuinely equals Customer Growth %
Customer Growth %'s actual DAX (DIVIDE(CurrentActive − PriorActive, PriorActive), with PriorActive via DATEADD(DimDate[Date],-1,MONTH)) resolves to the same point-in-time base as _Active Customers at Period Start, confirmed by checking the residual (New Customer Rate − Customer Growth %) across 20 months in a scratch table: it sits in a plausible 2.5–3 pp churn range throughout, and spikes to 4.5 pp in exactly one month — July 2024, one of the three simulated "churn wave" months built into this dataset from the original Phase 3 data generation, independently of this chart or its DAX. A false denominator mismatch would have no reason to land its error precisely on a calendar month already known to have elevated churn; this is stronger confirmation than comparing the two formulas side by side would have given. The reading note ("the gap between the lines is net customer growth") can be stated as exact, not approximate.
