Output 1 — Executive Conclusion

Three things must be settled before Page 3 design continues. None requires touching Pages 1 or 2.

Decision 1 — Rename Pages 3 and 6 (the root cause of the collision)

"Customer & Retention" and "Churn & Retention" both claim retention in their titles. That is not a labelling nuisance — it is why the Page 3 draft put "Logo churn by segment" as its largest visual, which is Page 6's core content. A boundary that has to be remembered will be forgotten; a boundary encoded in the page name enforces itself.

PageCurrent nameNew nameWhy
3Customer & RetentionCustomer GrowthRemoves "Retention" entirely. The page's job is the customer base's size and direction, not retention quality.
6Churn & RetentionRetention & ChurnRetention leads because cohort analysis is the page's most valuable content, not an afterthought to churn.

After renaming, the rule is mechanical: if a metric describes retention quality or churn causes, it is Page 6. If it describes customer counts and their direction, it is Page 3.

Decision 2 — Cohort retention is Page 6's primary object, and it is currently homeless

Cohort Retention % and Cohort Revenue Retention % — with the CohortAge table, the SignupMonth column, and a Python-validated curve (100% → 87.09% at 3mo → 82.95% at 6mo → 73.45% at 24mo → 69.37% at 30mo) — are the most sophisticated validated assets in Phase 3 and appear on no page in any design produced so far. This architecture assigns them as Page 6's hero visual, not a supporting one.

Decision 3 — Customer health has no home and must get one

FactCustomerHealth (25,283 rows: HealthScore, NPS, ProductUsage, SupportTickets) plus Avg Health Score at Churn (60.02) and Avg NPS at Churn (19.62) are unused. Health is the leading indicator of churn, so it belongs with churn diagnosis: Page 6. This also resolves the HealthScore banding question left open on Page 1 — if Page 6 needs categorical health tiers, that calculated column gets built once, for Page 6, deliberately.

What does NOT need to change
Pages 1 and 2 stay exactly as built. The redundancy audit below identifies two real issues on Page 1 (Output 4), but both are classified accept and document rather than fix — reopening finished, validated pages for a non-blocking structural point is how templates fail to ship. One optional improvement is recorded for Phase 5 QA, not now.

Output 4 — Redundancy Audit

Type 1 — Exact metric duplication

Issue B — Customer Growth % on Page 1
Finding: the Active Customers Tier 1 card already displays 3,587, ▲ +2.7%, and +93 net vs prior month. The Tier 2 Customer Growth % card displays 2.7% — the identical number, already visible 100 px above it. This is genuine Type 1 duplication: 1 of 8 P1 cards carries no independent information.

Verdict: accept and document, do not fix now. P1 is complete and validated; reopening it for a non-blocking point risks the regressions already seen twice in this build.

Optional Phase 5 improvement (recorded, not scheduled): Page 1 currently has zero representation of Page 4's entire domain — an executive overview with no unit-economics signal. Swapping Customer Growth % for Estimated LTV to CAC Ratio would remove a duplicate and close a domain gap in one move, without adding a card. Decide at Phase 5 QA.

Type 2 — Derived / repackaged duplication

Issue A — MRR and ARR both in Page 1 Tier 1
Finding: ARR = MRR × 12. Mathematically the same fact in two units, occupying 2 of 4 premium Tier 1 slots.

Verdict: keep both. The audiences differ in a way that matters: operators run the business in MRR (movement, churn, and expansion are all monthly), while boards, investors and valuation conversations happen in ARR. On a page whose stated job is serving a CEO, CFO and board simultaneously, showing only one forces half the audience to do mental arithmetic on the most important number in the company. The redundancy is real but justified — this is Type 4, not a defect.

Rule going forward: ARR appears on P1 and as P2 context only. It never gets its own trend chart anywhere — a second line with an identical shape to MRR adds nothing (the approved P2 spec already made this call).
Customer Retention % vs Logo Churn Rate
Finding: the Page 3 v1 draft placed Logo Churn Rate 2.4% and Customer Retention Rate 97.6% adjacent. These are the same number (100% − 2.4%).

Verdict: never place both on the same page. Page 3 uses Logo Churn Rate. Customer Retention % remains in the model for client deployments that prefer the positive framing — a documented template option, not a second KPI.

Type 3 — Analytical-story duplication

MRR Movement waterfall on both Page 1 and Page 2
Finding: the same visual, same measures, same month, built twice (P2's was literally copy-pasted from P1).

Verdict: accept. On P1 it is the only explanation available for the headline MRR number. On P2 it provides the single-month anchor that the 12-month composition chart beside it expands into a pattern. Removing it from either page would leave a real gap. Both pages are complete — this is documented, not actioned.
Logo churn by segment — the Page 3 / Page 6 collision
Finding: the Page 3 draft's largest bottom-right visual is a dimensional churn breakdown with a Segment/Plan/Channel/Health toggle — which is precisely Page 6's defined purpose.

Verdict: remove from Page 3 before design continues. This is the one redundancy in this audit that is both unbuilt and actionable. Page 3 keeps the Logo Churn Rate KPI card (a headline number belongs on the customer page); Page 6 owns every dimensional breakdown of churn.

Output 5 — Page Boundary Rules

Page 1 vs Pages 2–6

  • P1 may repeat any metric, but only as a KPI card or a shape-only trend — never as a dimensional breakdown, never with a toggle, never as a matrix.
  • If a P1 visual requires the user to interact to understand it, it belongs on another page.
  • P1 owns exactly one thing exclusively: the Executive Insight narrative card.
  • Tier 1 cards are never cross-filter targets (already implemented).

Page 2 vs Page 5

  • P2 asks how revenue moves over time. P5 asks who the revenue comes from.
  • P2 may show one dimensional cut (the Plan/Segment matrix). P5 compares multiple dimensions — segment, plan, industry, country, channel.
  • If a visual has a time axis, it is P2's. If it compares categories at a point in time, it is P5's.

Output 6 — Target / Benchmark Architecture (design only, not implemented)

A · The table

The proposed schema is close but needs three changes. Evaluated version:

ColumnTypePurpose
MetricKeyTextStable identifier matching a measure name exactly. Added — joining on a display label breaks when a label is reworded.
MetricDisplayNameTextWhat the user sees
TargetValueDecimalThe number to compare against
DirectionTextAdded, and essential. "Higher is better" / "Lower is better". Without it, variance logic cannot colour churn and growth correctly — the same trap already hit on the Logo Churn card.
ToleranceBandDecimalAdded. Enables a three-state verdict (on target / at risk / off target) rather than a binary hit-or-miss, which is how management actually reads targets.
BenchmarkTypeText"Client target" / "Board commitment" / "External benchmark"
EffectiveFrom / EffectiveToDateTargets change annually. A single EffectiveDate cannot express a closed period.
SourceNoteTextProvenance — mandatory for external benchmarks

Grain: one row per metric per effective period. Loaded from an editable source (Excel/CSV) so a client replaces values without touching the model.

B · Which metrics genuinely benefit

MetricTarget?Reasoning
MRR Growth %YesEvery SaaS company plans against a growth rate
Logo Churn RateYesThe canonical managed target; needs Direction = lower is better
NRRYesBoard-level metric with a well-understood 100% threshold
GRRYesPairs with NRR
LTV:CACYesThe 3:1 convention is widely used as a planning target
CAC PaybackYesCash-planning target; lower is better
MRR / ARRYesAbsolute plan numbers — the most common management target of all
ARPAOptionalUsually an outcome of pricing/mix, not a managed target
Active CustomersOptionalSometimes planned, often derived
Cohort retentionNoA curve, not a point; a single target value would misrepresent it
Movement componentsNoComponents of a total, not independently managed

C · How targets are used — three measures total, not one per metric

Build a generic pattern, not 8 × 4 = 32 measures:

  • Target Value — looks up the active target for the metric in context
  • Variance to Target — actual − target, sign-corrected by Direction
  • Target Status — returns a status string/colour using ToleranceBand

Rendered as a reference line on trend charts and a small status indicator on KPI cards — reusing the existing glyph + sign + colour pattern already built, so no new visual language is introduced.

D · Reusability & E · Sources

  • Ships with the table present but empty, plus a documented sample row. An empty table must degrade gracefully: every target measure returns blank and every KPI renders exactly as it does today.
  • No invented industry benchmarks. The template supplies the mechanism; the client supplies the numbers. Where an external benchmark is used, SourceNote must name it.
  • Phase 5 packaging includes a one-page "how to set your targets" note.

Implementation phase: Phase 5. Not now.

2 · Repetition rules

  1. A metric appears on its home page in full analytical context.
  2. A metric may appear on Page 1 as a KPI card or shape-only trend — never as a breakdown, toggle or matrix.
  3. A metric may appear on another page only when that page's question genuinely requires it as context.
  4. Two metrics that are arithmetic transforms of each other never share a page (Customer Retention % / Logo Churn Rate; MRR / ARR outside P1's deliberate exception).
  5. A metric already displayed inside another card's delta line does not also get its own card on the same page.
  6. Repetition of an entire visual requires written justification, not just repetition of a measure.

3 · Page boundary tests

  • Time axis? → P2 (revenue) or P3 (customers). Category comparison at a point in time? → P5.
  • Cohort age axis rather than calendar? → always P6.
  • Explains why a customer left? → always P6.
  • Dimension is acquisition channel? → P4. Dimension is a customer attribute? → P5.
  • Needs interaction to be understood? → never P1.

4 · Explicit exclusions

Forecasting & Planning — Future Project / Future Enhancement. Out of scope for this template: no forecast visuals, measures, requirements or architecture. Recorded once here; not to be raised again as a current gap.

5 · Design governance rule

Before designing any new page: every proposed visual and measure must be assigned a home in the ownership matrix before implementation begins. If a proposed visual has no home, it is either misplaced or the architecture needs an explicit amendment — decide which before building, never after.

6 · Amendment rule

This architecture is FROZEN. Reopen only for: correctness, a genuine analytical gap, serious redundancy, misleading communication, implementation impossibility, or an important usability problem. Never for aesthetic preference.

Decision rules (portable to any project)

  1. Arithmetic-transform rule. If metric B is a fixed transform of metric A (B = 100% − A, B = A × 12), they never share a page unless a named audience genuinely needs each unit.
  2. Delta-line rule. A number already shown inside another card's comparison line does not get its own card on that page.
  3. Interaction rule. A visual requiring interaction to interpret never belongs on an executive summary page.
  4. Axis rule. Time axis → trend page. Category axis → comparison page. Age/cohort axis → retention page.
  5. Story rule. Two visuals answering the same business question are duplication even when built from different measures.
  6. Sparse-page rule. After removing redundancy, do not backfill with low-value charts. A clean page with four meaningful visuals beats a dense page with seven.
  7. Homeless-measure rule. A validated measure with no page is either a missing page or a measure that should be retired. Both are decisions; neither is "leave it."
